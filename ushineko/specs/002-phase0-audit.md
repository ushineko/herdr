# Phase 0 audit: pane-enumeration sites vs. the pane-stack invariant change

Scope: branch `ushineko/pane-stacks` (herdr v0.9.5 + the spaces bar and dock), read-only. Line numbers are as of commit `e409d67d`.
Planned model (spec `ushineko/specs/002-nested-tabs.md`): `Tab::panes` (and `DockLayout::panes`) = layout leaves + hidden stack members; only the visible member of a stack is a `TileLayout` leaf.

Method: a script listed every line in `src/` matching `.pane_ids()`, `.pane_count()`, `layout.panes(..)`, `panes_after_split(..)`, `layout.root()`, and every use of the `panes` field (`tab.panes`, `self.panes` in `Tab`, `dock.panes`), excluding `#[cfg(test)]` items, files pulled in by `#[cfg(test)] mod x;`, `*_tests.rs` and `tests/`. Each hit was then read in context. `TileLayout`'s public enumerators (`src/layout.rs`): `pane_count()` (l.121), `panes(area)` (l.126), `panes_after_split()` (l.135), `splits()` (l.156, split borders only, not panes), `pane_ids()` (l.344), `root()` (l.351, tree walk for serialization), `focused()` (l.117). No other leaf iterator exists.

Production runtimes are NOT stored in `Tab` (`Tab::runtimes` is `#[cfg(test)]`, `src/workspace/tab.rs:46-47`); they live in `App::terminal_runtimes: TerminalRuntimeRegistry` keyed by `TerminalId`, and `PaneState::attached_terminal_id` links a pane to it. So "all-panes" for lifecycle means "iterate `tab.panes` and map to terminal ids".

Client-side code (`src/client/**`) has no `Tab`; it consumes server projections: `surface.panes` (pane-surface frames, visible by construction) and `snapshot.panes` (built from `session_snapshot`, row 22). Client sites are not tabulated individually; their behaviour follows rows 22/23 (see Risk summary, "client snapshot").

Legend: class **V** = visible-only, **A** = all-panes, **—** = not an enumeration in the stack sense (bookkeeping / config). Verdict **OK** = OK as-is, **NC** = NEEDS CHANGE.

## 1. Workspace/AppState invariant checks and adversarial fixtures

- `Workspace::assert_invariants_for_test` — `src/workspace.rs:1287-1427` (inside `#[cfg(test)] impl Workspace`, l.1168). Asserts: ≥1 tab; `active_tab` in bounds; public tab numbers >0 and unique; each tab's `root_pane` ∈ `tab.panes` (l.1319-1325); layout has no duplicate ids (l.1327-1335); `layout.focused()` ∈ layout (l.1336-1342); **`layout_set == pane_set` (l.1343-1348) — the line that must change**; each pane in only one tab, has a public number, and has a unique `attached_terminal_id` (l.1350-1369); `next_public_tab_number > max`; public pane map keys == live panes (l.1387-1392); public pane numbers >0, unique, `< next_public_pane_number`.
- `AppState::assert_invariants_for_test` — `src/app/state.rs:1157-~1310`. Calls the workspace check per workspace (l.1225), then: pane ids unique across workspaces, terminal ids unique, every attached terminal exists in `terminals` (l.1227-1246); raw/public pane aliases, `previous_pane_focus`, toast target, pending agent notifications, popup, and plugin pane records reference live panes (l.1248-1308).

## 2. Live handoff enumeration

- Export (`src/server/headless/lifecycle.rs:25-140`, `perform_live_handoff`): `pane_by_terminal` is built from **every `tab.panes` entry** (l.48-55). Readers are paused for those terminals (l.61-70), the snapshot is `persist::capture` + `dock_snapshot` (l.72-79), and `handoff_entries` = every runtime in `terminal_runtimes` that maps to such a pane (l.81-103). So hidden members' runtimes and fds ARE sent. Dock runtimes are not in `pane_by_terminal` and are not transferred; the dock restarts from its snapshot (`src/app/mod.rs:757-758`).
- Import (`src/server/headless/bootstrap.rs:134-152` → `App::new_from_handoff`, `src/app/mod.rs:699-760` → `persist::restore_handoff`, `src/persist/restore.rs:96-120` → `restore_with_imports_strict`, l.189-227): `restore_tab` consumes an import only for panes in the restored **tree** (l.508, 581). After restore, **any unconsumed import is an error** (`restore.rs:219-224`: "handoff import did not consume N pane runtime(s)").
- Consequences: (a) with stacks, the importer must also restore stack members, or every handoff fails; (b) **a live handoff from the stacks build to stock herdr always fails** while any stack exists (stock does not consume hidden runtimes). The failure path rolls back to the old server (characterised by `tests/live_handoff.rs:2037 live_handoff_import_failure_rolls_back_old_server_at` / `:2118 live_handoff_after_restored_failure_rolls_back_old_server`), so it is safe but means rollback to stock needs a cold restart (hidden processes die, stock respawns only visible panes). (c) `handoff_pane_aliases` (row 58) and `restore_workspace` public numbers (row 57) are tree-only.

## 3. Session save and restore enumeration; stock tolerance

- Save: `persist::capture` (`src/persist/snapshot.rs:302-325`) → `capture_workspace` (l.327-363; `public_pane_numbers` copied from the workspace map, so hidden numbers are saved) → `capture_tab` (l.365-442): `panes` from **`tab.panes.keys()`** (all), `layout` from `capture_node(tab.layout.root())` (tree), `focused` = `layout.focused()`, `root_pane` = `tab.root_pane` (may be a hidden member). History: `capture_tab_history` iterates `tab.panes` (l.480-490). `capture_layout` (`src/persist.rs:24`) is only used by the dock (`src/app/dock.rs:637`); dock `panes` come from `dock.panes` (all, l.640-660).
- Restore: `restore_tab` (`src/persist/restore.rs:491-811`) walks the remapped tree ids only (l.503-516) and looks up `snap.panes.get(old_id)`. **Extra `snap.panes` entries not in the tree are never read** — tolerated silently. `restore_workspace` assigns public numbers only for `tab.layout.pane_ids()` (l.388); `migrated_public_pane_numbers_by_old_raw` (l.159-176) starts from the saved map (incl. hidden) and `next_public_pane_number` ≥ saved max+1 (l.331-338), so stock never reuses a hidden member's number. `root_pane`/`focused` that are not in the tree fall back to the first tree pane (`resolve_restored_pane`, l.948-958). Snapshot structs have no `deny_unknown_fields` (grep of `src/persist*` empty), so a new `stacks` field is dropped by stock serde.
- Dock restore (`src/app/dock.rs:669-707`) likewise builds panes from the tree id map only; extra saved dock pane entries are ignored.
- Caveat (not verified against a stock binary): pane-history validity uses `layout_fingerprint` = SHA-256 of the re-serialized snapshot (`snapshot.rs:444-454`, check at `restore.rs:271-279`). Stock re-serializes without `stacks`, so if `stacks` is serialized the fingerprint differs and stock discards saved scrollback for the whole session (logs "Ignoring pane history without a matching session layout"). Use `skip_serializing_if` empty so stack-free sessions keep identical fingerprints. Whether the dock field already causes this for rollback is unverified.
- Template tests for the stock-compat AC: `src/persist/snapshot.rs:576 a_saved_dock_round_trips_and_keeps_the_snapshot_version`, `:620 sessions_without_a_dock_or_with_an_unreadable_one_still_restore` (parses a "stock" JSON).

## Risk summary (all NEEDS CHANGE, grouped)

**A. "Last pane in tab" uses leaf count — data loss / leaked processes (critical).** Rows 18, 42, 43, 45, 47, 33, E3; dock 65, 68. With a one-slot stack, closing, moving, or the death of ANY member is treated as the tab's last pane: the tab (or the whole workspace) is removed, only that one terminal is detached, other members' runtimes keep running unowned and their public numbers stay registered. Fix: `tab.panes.len()` for "last pane"; leaf removal of a visible member must become `replace_pane` with the next member.

**B. Lists that hide hidden agents/panes.** Rows 22 (session snapshot, feeds client Go To / notifications), 23 (`agent list`), 24 (name targets), 25 (`pane list`), 38 (sidebar details), 9/10 (metadata expiry).

**C. Lifecycle tied to geometry.** Rows 20/21 (deferred agent resume never starts for a hidden pane), 13/E4 (worktree removal leaves hidden processes running), 15/27/13 (plugin records leak), 63/71 (hidden dock members never spawned/restored), 61/72 (dock sizes).

**D. Persistence / handoff.** Rows 55, 57, 58, 71: restore and handoff import walk the tree only; with hidden runtimes in the manifest the strict import fails every handoff until restore learns stacks. Rollback to stock via live handoff is impossible while stacks exist (fails safely, old server stays); cold rollback loses hidden panes' processes (expected) and probably saved scrollback (fingerprint caveat, item 3).

**E. Render hot path.** Row 78: `any_shell_surface_contains_pane` uses `tab.panes`, so hidden members would be treated as visible. The spec's premise that the hidden-source early exit already works is false; this must change and be pinned by a test.

**F. Sizing.** Rows 87, 88, 84, 61: hidden members are never resized (stale size, not zero).

**G. Focus / visibility semantics (decisions).** E1 (focus/Go To/agent focus on a hidden pane silently does nothing yet reports success), 30/31 (geometry APIs on a hidden pane return not-found), 35, 67, 11/40/19/E2 (seen marking and notification suppression treat hidden members of the active tab as seen/visible).

**Containment assessment.** No site was found that makes the change unsafe to contain: every NEEDS CHANGE site is a local substitution (`layout.pane_ids()` → `tab.panes`, or `pane_count()` → `panes.len()`) or a new stack-aware helper (`is_visible`, `reveal`, `replace_pane`, "size hidden like visible"). The hazards are (1) group A, which is silent today: no existing test exercises a tab whose `panes` exceed its leaves, so every listed close/move/death path needs a new stack test before code moves; (2) group D, the strict handoff import, which turns any missed restore path into a failed (rolled-back) handoff, and blocks live rollback to stock; (3) row 78, which contradicts the spec text. Unverified: the fingerprint/scrollback effect on stock rollback, and whether any client code assumes `snapshot.panes` ⊆ surface panes beyond the sites cited in row 22.
